设计模式核心思想与实践

发表于 2026-05-11 分类于 软件设计
从设计原则到常见模式，系统理解设计模式背后的核心思想与落地方式

设计模式核心思想与实践

前言

设计模式不是为了炫技而存在，它本质上是前人对常见软件设计问题的总结。很多人第一次接触设计模式时，容易把重点放在类图和定义上，但真正重要的并不是记住多少个模式，而是理解这些模式分别在解决什么问题。

写代码的过程，本质上是在处理变化。需求会变，依赖会变，业务边界会变，系统规模也会变。设计模式的价值，就在于帮助我们用更稳定的方式去应对这些变化。

概览总览

如果只看分类，设计模式很多；但如果从“解决什么问题”的角度看，可以归纳为四类核心思想：

核心问题 代表模式 解决思路
对象怎么创建 工厂、单例、建造者 把对象创建过程与使用过程解耦
类和对象怎么组合 代理、适配器、装饰器 通过组合替代继承，增强扩展性
行为怎么切换 策略、状态、命令 把行为抽象出来，运行时动态替换
流程怎么编排 模板方法、责任链、观察者 将流程标准化或解耦事件传播

一、创建型模式（5 种）

模式 一句话描述 框架代表示例 高频使用程度
单例模式 确保类只有一个实例，并提供全局访问点 Spring 默认 Bean 作用域就是单例 ⭐⭐⭐⭐⭐ 极其高频
工厂方法 定义创建对象的接口，子类决定实例化哪个类 MyBatis MapperProxyFactory 生成 Mapper 代理 ⭐⭐⭐⭐⭐ 极其高频
抽象工厂 创建一系列相关或相互依赖的对象 Spring FactoryBean，如 SqlSessionFactoryBean ⭐⭐⭐ 中频
建造者模式 将复杂对象的构建与表示分离 MyBatis SqlSessionFactoryBuilder 一步步构建 ⭐⭐⭐ 中频
原型模式 用原型实例指定创建对象的种类，通过拷贝创建 Spring @Scope("prototype")，每次获取新建 Bean ⭐⭐⭐ 中频

二、结构型模式（7 种）

模式 一句话描述 框架代表示例 高频使用程度
适配器模式 将一个类的接口转换成客户期望的另一个接口 Spring MVC HandlerAdapter 适配不同 Controller ⭐⭐⭐⭐ 高频
桥接模式 将抽象与实现分离，使它们独立变化 JDBC 抽象驱动接口与各数据库实现分离 ⭐⭐⭐ 中频
组合模式 把对象组合成树形结构表示”部分-整体” Spring Security SecurityConfigurer 树形配置 ⭐⭐ 低频
装饰器模式 动态地给对象增加额外职责 MyBatis Cache 装饰器链 (LruCache → PerpetualCache) ⭐⭐⭐⭐ 高频
外观模式 为子系统提供统一入口 MyBatis SqlSession 封装配置、执行、事务等 ⭐⭐⭐⭐ 高频
享元模式 共享技术支持大量细粒度对象复用 MyBatis 一级缓存 (PerpetualCache in BaseExecutor) ⭐⭐⭐ 中频
代理模式 为对象提供代理控制访问 Spring AOP JdkDynamicAopProxy 拦截方法织入切面 ⭐⭐⭐⭐⭐ 极其高频

三、行为型模式（11 种）

模式 一句话描述 框架代表示例 高频使用程度
责任链模式 多个对象都有机会处理请求，避免耦合 Spring MVC HandlerInterceptor 链，preHandle 顺序调用 ⭐⭐⭐⭐⭐ 极其高频
命令模式 把请求封装成对象 MyBatis MappedStatement 封装 SQL 映射 ⭐⭐ 低频
解释器模式 定义语言文法并解释 Spring EL SpelExpressionParser 解析表达式 ⭐⭐ 低频
迭代器模式 顺序访问聚合元素，不暴露内部表示 MyBatis DefaultCursor 流式处理大结果集 ⭐⭐⭐ 中频
中介者模式 中介对象封装交互，减少耦合 Spring MVC DispatcherServlet 协调各组件 ⭐⭐⭐ 中频
备忘录模式 捕获对象内部状态并存储 Spring Web Flow FlowExecutionRepository 状态快照 ⭐ 极低频
观察者模式 一对多依赖，状态变化通知依赖者 Spring 事件机制 ApplicationEvent + @EventListener ⭐⭐⭐⭐ 高频
状态模式 对象内部状态改变时改变行为 Spring Statemachine 状态机 ⭐ 极低频
策略模式 定义算法族，分别封装互相替换 Spring InstantiationStrategy（Bean 实例化策略） ⭐⭐⭐⭐⭐ 极其高频
模板方法模式 定义算法骨架，延迟步骤到子类 MyBatis BaseExecutor 定义查询骨架，子类实现细节 ⭐⭐⭐⭐⭐ 极其高频
访问者模式 不改变元素类前提下增加新操作 Spring BeanDefinitionVisitor 遍历元数据 ⭐ 极低频

详细解析

创建型模式

创建型模式关注的是：对象应该如何被创建，才能让系统更灵活。

单例模式

单例模式保证一个类在系统中只有一个实例，常用于配置中心、线程池、缓存管理器等场景。

适用场景：

  • 资源需要全局共享
  • 创建对象成本高
  • 需要统一访问入口

注意点：

  • 线程安全
  • 反射破坏单例
  • 序列化破坏单例

工厂方法模式

工厂方法模式把“创建对象”的逻辑抽到工厂里，调用方只依赖抽象，不依赖具体实现。

核心价值：

  • 隔离对象创建细节
  • 降低调用方对具体类的依赖
  • 符合开闭原则

建造者模式

建造者模式用于构建复杂对象，尤其适合字段多、构造过程复杂的对象。

适用场景：

  • 参数很多且有可选项
  • 需要链式构建
  • 想避免构造函数重载爆炸

结构型模式

结构型模式关注的是：如何组织类和对象之间的关系。

代理模式

代理模式通过一个代理对象控制对目标对象的访问。

常见应用：

  • Spring AOP
  • MyBatis Mapper 代理
  • RPC 远程调用代理

适配器模式

适配器模式的本质，是让两个原本不兼容的接口协同工作。

核心价值：

  • 兼容旧系统
  • 接入第三方 SDK
  • 降低改造成本

装饰器模式

装饰器模式是在不修改原对象的前提下，动态增强对象功能。

常见应用：

  • Java IO 流体系
  • Spring Wrapper 体系
  • 动态功能叠加

行为型模式

行为型模式关注的是：对象之间的职责如何协作，行为如何变化。

策略模式

策略模式把一组可替换的算法抽象出来，在运行时动态选择。

适用场景：

  • 支付方式切换
  • 排序规则切换
  • 风控策略切换

模板方法模式

模板方法模式把流程骨架定义在父类中，把具体实现延迟到子类完成。

适用场景：

  • 流程固定，但局部实现不同
  • 框架设计中的扩展点

责任链模式

责任链模式将多个处理器串成链，请求沿着链传递，直到被某个处理器消费。

常见应用：

  • Servlet Filter
  • Spring Security 过滤链
  • 审批流系统

观察者模式

观察者模式定义了一对多的依赖关系，一个对象状态改变时，所有依赖它的对象都会收到通知。

常见应用：

  • 事件通知系统
  • 消息订阅
  • GUI 事件监听

总述

设计模式的本质，不是记忆 23 种模式的名字，而是理解软件设计中的几类高频问题，以及它们的通用解法。

创建型模式解决的是“对象怎么创建才不会把系统写死”；结构型模式解决的是“对象之间怎么组合才更灵活”；行为型模式解决的是“流程和行为怎么变化才不会牵一发而动全身”。

从更高的角度看，设计模式并不是独立存在的技巧，而是对“高内聚、低耦合、面向抽象、组合优于继承”这些设计原则的具体落地。很多优秀框架，比如 Spring、MyBatis、Netty，本质上都是这些模式的组合应用。

真正掌握设计模式的标志，不是能背出类图，而是遇到问题时，能够自然想到：这里是不是要把创建过程隔离出来？这里是不是应该把行为抽象成策略？这里是不是该用责任链解耦流程？

延伸思考

设计模式与设计原则的关系

设计模式并不是孤立的，它们通常建立在以下原则之上：

原则 含义 典型模式
单一职责原则 一个类只做一件事 策略、责任链
开闭原则 对扩展开放，对修改关闭 工厂、装饰器
依赖倒置原则 依赖抽象而不是实现 工厂、代理
组合复用原则 多用组合，少用继承 装饰器、桥接

什么时候不该用设计模式

不是所有代码都值得抽象。以下场景不必强行上模式：

  • 业务很简单且变化不大
  • 只有一次性逻辑
  • 引入模式的复杂度高于收益
